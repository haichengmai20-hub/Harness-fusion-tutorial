# s10 源码研读样章

在 Learn Claude Code 的 s10 章节，选「按需拼接」或「缓存避免重复拼接」。两组各有四道题，右栏「源码研读」会跟随选择。每道题给出教学实现、固定快照里的调用路径、旧笔记中应回看的解释以及一个可以自己检查的判断。[样章入口](http://127.0.0.1:8765/?primary=claude&mode=original&chapter=s10)

## 从一个观察走到源码

1. 在「按需拼接」里看“写完 MEMORY.md，哪一次请求才读到新规则”。找到网页对应版本的 `update_context` 和 `get_system_prompt`，分别指出哪一行读文件、哪一行只是复用字符串。作业里的八问是已有运行记录，第三方快照的静态实现另有独立入口。
2. 切到「缓存避免重复拼接」。顺着「最后一个工具和最后一条消息一定有标记吗」的引用，从请求构造器往前读实际传参，再看旧笔记对应小节。某个类型接受 `cache_control`，仅能证明可以编码该字段；当前调用是否传入它要读调用点。读命中量要查该次响应的 `usage`。
3. 打开「Harness Lab · 比较两次请求」，在真实 `ProfilerAgent` 入口换一个近期标题，再单独改工具说明，两次和基线逐字段比对。此处能观察 SDK 入参，服务端是否命中须另有服务端响应。[实验与实际输出](../docs/s10-harness-lab.md)

## 下一章如何接入

先在原课的一个具体段落提出同一问题，再找到快照里能回答它的执行路径，最后回到旧笔记核对其版本、触发条件和证据。适合继续做的例子有 s07 的技能目录与技能正文、s08 的历史裁剪与摘要、s09 的索引与异步召回。它们目前是候选。

新章在 `data/chapter-readings.json` 登记阅读材料，按 s10 的结构添加内容文件。每条的 `point` 对应本章原有定位点的序号，从 1 开始。`refs` 给出资料名、相对工作区的位置与真实行号。逐行检查后再用浏览器验证定位点变更时显示的题目。未核实的生产效果可以写成待检查的问题。对真实 Lab 有合适入口时，可另加一份与该问题直接关联的实验记录。

本机运行 `python -B study.py serve` 再用 VS Code 或 Cursor 跳到文件。单独克隆本项目时，课程、已发布的三个读本和研读题仍可阅读。要打开本机源文件，需要相应源码或同级笔记目录。生成新读本可以使用 Pandoc；无 Pandoc 时优先使用随仓交付且摘要匹配的 HTML，变更后的笔记仍可按完整 Markdown 文本阅读。
