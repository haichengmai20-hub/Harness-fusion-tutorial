## 对照能否回答原文的问题

20 章共有 48 个原文定位点。每处给三家各自的回答、对应程度和固定版本源码链接，共 144 条。首页“核心模式”和“消息增长”另设对照。浏览器逐个选择章节定位点，核对选区命中原文字串、选区在视口内、旁注问题正确，以及三家均有说明和来源。另核对切换框架时左页所在文档、页签和滚动位置，以及窄屏返回原文。[逐点数据](../data/original-crosswalk.json) · [读者操作记录](original-verification-reader.json)

三种有判别力的例子：

- s03 终端命令与 ACP 文件编辑走不同入口。Hermes 对照链接直接定位命令执行前的审批路径。
- s08 将旧历史裁剪、旧工具结果占位、大结果落盘、全量摘要分开。能裁剪上下文的代码，只能支撑它实际实现的那一项。
- s11 把输出截断、上下文超限、临时请求故障分别定位。一个分支能识别停止原因，与它是否继续生成或重发请求，需要分别确认。

144 处源码引用已逐条核过固定文件与行号。对权限、压缩、恢复、后台任务、认领、工作树、MCP 和集成八章，另复核 66 条说明的适用条件。对应关系是静态源码判断，产品在具体配置下的实际行为仍需独立运行。原文全部保留；对照范围为标出的机制检查点。[逐章核验说明](original-crosswalk.md)

本版逐点判断为 73 条对应、55 条部分对应、16 条待核。这组数字按“原课问题 × 框架”计数；旧实验里的 60 张章级背景卡沿用自己的统计范围。

## 重现

从项目根目录运行：

```powershell
python -B tools/snapshot_original.py
python -B study.py build
python -B -m unittest discover -s tests -v
python -B study.py serve
```

保持服务开启，在另一终端运行浏览器核验：

```powershell
node tests/original-browser.mjs verify http://127.0.0.1:8765
node tests/original-browser.mjs reader http://127.0.0.1:8765
```

阅读时使用本地 HTTP 加载归档的前端资源。GitHub 原始源码链接和外语原站页面仍需联网。购物车单文件实验与这份原课分开验收。[实验验收](acceptance.md) · [桌面原文定位截图](screenshots/original-s03-located.png) · [窄屏对照截图](screenshots/original-mobile-comparison.png)
